# Kimi model controls in official Happier

The Studio uses official Happier and Kimi Code CLI binaries. 9Router owns the
model catalog and a small ACP discovery adapter, `scripts/studio-kimi-acp.mjs`.
The adapter reads the local `/v1/models` catalog once when Kimi ACP starts and
adds missing per-model Thinking controls to native session discovery. It only
advertises effort values supported by both the router model and native CLI.
The native CLI still handles model switching, thinking selection, prompts,
permissions, tools, and sessions. No inference is used for discovery.

The existing 9Router Happier profile supplies:

- `KIMI_CODE_HOME`: isolated config generated by `scripts/studio-kimi-config.py`.
- `ANTHROPIC_AUTH_TOKEN`: existing 9Router token, never the Moonshot key.
- `HAPPIER_KIMI_PATH`: absolute path to
  `9router-studio/current/scripts/studio-kimi-acp.mjs`.

The adapter launches `~/.kimi-code/bin/kimi`. `STUDIO_KIMI_NATIVE_PATH` can
override that path. `STUDIO_KIMI_CATALOG_URL` may point to another HTTP loopback
router catalog; redirects and remote destinations are refused. A failed or
slow catalog read falls back to the native discovery response. Non-ACP commands
are passed directly to Kimi, including `--version` and help. Future native
per-model metadata takes precedence over this compatibility adapter.

The standalone release includes the executable adapter. The profile follows
the atomic `current` release link, so normal fork updates carry the integration
forward without rebuilding Happier. After changing its catalog or profile,
refresh the model picker to bypass Happier's discovery cache.

Validation: `npm --prefix tests run test:studio` covers metadata, transport
passthrough, process cleanup and packaging. Live acceptance must also verify
both models' Low/High/Max choices through official Happier discovery and model
switching in native Kimi ACP. Never change an existing user's session for QA.
